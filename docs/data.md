# Data Management

What data exists in this project, where it lives, what it is needed for, and
what is versioned in git. Read this before deploying or wondering why the repo
does not contain the actual routing data.

## Inventory

| Path | Size | Role | Phase | In git |
|---|---|---|---|---|
| `data/regions.json` | small | Catalog of downloadable OSM extracts (Geofabrik) | Build only | **Yes** |
| `data/spain.osm.pbf` | ~1.4 GB | Raw OSM extract of Spain | Build only | No (re-downloadable) |
| `valhalla/config/valhalla.json` | small | Valhalla configuration | Build + runtime | **Yes** |
| `valhalla/config/admins.sqlite` | ~23 MB | Administrative boundaries | Build only | No (generated) |
| `valhalla/config/timezones.sqlite` | ~116 MB | Timezone data | Build only | No (generated) |
| `valhalla/tiles/` + `tiles.tar` | ~2.1 GB | Routing graph | Runtime | No (generated) |
| `valhalla/elevation/` | ~1 GB | Elevation tiles (.hgt.gz) | Runtime | No (re-downloadable) |
| `data/elevation/` | empty | Unused; reserved name only | - | No |

Everything except the config is generated by scripts or downloaded. A fresh
clone contains only code, scripts and docs.

## Build-time vs runtime

The key distinction: **the OSM PBF is never needed at runtime**, and
**elevation tiles are never served to clients at runtime** — they are a build
input (grades get baked into the graph) and a runtime input for `/height`.

```
BUILD (offline, one-off)                 RUNTIME (server)
├── data/spain.osm.pbf                   ├── valhalla/config/valhalla.json
├── valhalla/elevation/*.hgt.gz          ├── valhalla/tiles/ (+ tiles.tar)
│        │                               └── valhalla/elevation/   (for /height)
│        ▼                                     │
│   download_elevation.sh                     ▼
│   └──> elevation/*.hgt.gz             docker-compose (port 8002)
│                                       valhalla_service /data/config/valhalla.json 4
│   build_tiles.sh (needs PBF + elevation)
│   ├──> config/valhalla.json
│   ├──> config/admins.sqlite
│   ├──> config/timezones.sqlite
│   └──> tiles/ + tiles.tar  (grades baked in)
```

## Production deployment

To serve routing requests you need exactly:

1. The Docker image: `ghcr.io/valhalla/valhalla:3.8.2`
2. `config/valhalla.json`
3. `tiles/` (or just `tiles.tar`, which the config references as extract)
4. `elevation/` — optional at runtime: `/height` needs it, routing does not
   (grades are already baked into the tiles). Required again whenever you
   rebuild the graph.

You do **not** need: the `.osm.pbf`, the sqlite files, or any script.
Mount the directory as `/data` and run:

```bash
valhalla_service /data/config/valhalla.json <threads>
```

That is what `docker-compose.yaml` does with `./valhalla:/data`.

## Regenerating everything from scratch

On a fresh machine (or after wiping `valhalla/`):

```bash
# 1. Download the OSM extract into data/spain.osm.pbf (~1.4 GB)
./scripts/download_osm.sh spain

# 2. Build config + admins + timezones + routing tiles (~8 min)
./scripts/build_tiles.sh

# 3. Download elevation tiles for the whole graph (~1 GB)
./scripts/download_elevation.sh

# 4. Start and validate
docker compose up -d valhalla
./scripts/smoke_test_height.sh
```

Or all of it at once: `./scripts/setup_valhalla.sh --region spain`.

## Adding a new region

Add an entry to `data/regions.json` (Geofabrik publishes one `-latest.osm.pbf`
per region), then:

```bash
./scripts/setup_valhalla.sh --region portugal
```

Note: each region currently builds its own routing space; merging several
PBFs into a single graph is planned but not implemented yet
(`valhalla_build_tiles` accepts multiple inputs).

## Git hygiene

`.gitignore` excludes every large/generated artifact:

- `data/*.osm.pbf` — source data, re-downloadable from Geofabrik
- `valhalla/tiles/`, `valhalla/tiles.tar` — generated by `build_tiles.sh`
- `valhalla/elevation/` — re-downloadable via `download_elevation.sh`
- `valhalla/config/*.sqlite` — generated by `build_tiles.sh`
- `valhalla/valhalla/` — junk path from an earlier manual run (raw Copernicus
  TIFF intermediates); safe to delete from disk

Only code, scripts, docs, `data/regions.json` (the region catalog) and
`valhalla/config/valhalla.json` (small, and the canonical reference
configuration) are versioned.
