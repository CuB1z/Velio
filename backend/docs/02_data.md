# Data Management

What data exists in this project, where it lives, what it is needed for, and
what is versioned in git. Read this before deploying or wondering why the repo
does not contain the actual routing data.

## Inventory

| Path | Size | Role | Phase | In git |
|---|---|---|---|---|
| `data/regions.json` | small | Catalog of downloadable OSM extracts (Geofabrik URL, boundary polygon, ISO code) | Build only | **Yes** |
| `data/<region>.osm.pbf` | see below | Raw OSM extract per region | Build only | No (re-downloadable) |
| `data/<region>.poly` | < 25 kB | Geofabrik boundary polygon per region | Build only | No (re-downloadable) |
| `data/coverage.osm.pbf` | ~2.0 GB | The region extracts merged into one file | Build only | No (generated) |
| `data/coverage.geojson` | ~16 kB | Simplified boundary of every covered region | Runtime (baked into the API image) | **Yes** |
| `data/restricted_areas.geojson` | ~2.0 MB | Military areas and airfields the loop engine avoids | Runtime (baked into the API image) | **Yes** |
| `valhalla/config/valhalla.json` | small | Valhalla configuration | Build + runtime | **Yes** |
| `valhalla/config/admins.sqlite` | ~27 MB | Administrative boundaries | Build only | No (generated) |
| `valhalla/config/timezones.sqlite` | ~116 MB | Timezone data | Build only | No (generated) |
| `valhalla/tiles/` + `tiles.tar` | ~2.7 GB each | Routing graph | Runtime | No (generated) |
| `valhalla/elevation/` | ~1.2 GB | Elevation tiles (.hgt.gz) | Runtime | No (re-downloadable) |
| `data/elevation/` | empty | Unused; reserved name only | - | No |

Everything except the config, the region catalog and the two GeoJSON files is
generated by scripts or downloaded. A fresh clone contains only code, scripts,
docs and those small files.

## Covered regions

The default build covers four Geofabrik extracts, merged into one graph:

| Key | Extract | Size (2026-10-11) | Notes |
|---|---|---|---|
| `spain` | `europe/spain` | 1.49 GB | Mainland, Balearics, Ceuta and Melilla. **No Canary Islands.** |
| `canary-islands` | `africa/canary-islands` | 60 MB | Geofabrik files the Canaries under Africa |
| `portugal` | `europe/portugal` | 425 MB | Mainland, Azores and Madeira |
| `andorra` | `europe/andorra` | 3.5 MB | Keeps Pyrenees loops across the border routable |

Neighbouring extracts overlap along their borders (each one keeps the ways
that cross it). `tools/merge_regions.py` merges them with pyosmium and keeps one
copy of every object, so tiles, admins and restricted areas all read the same
deduplicated file.

## Build-time vs runtime

The key distinction: **the OSM PBFs are never needed at runtime**, and
**elevation tiles are never served to clients at runtime** — they are a build
input (grades get baked into the graph) and a runtime input for `/height`.

```
BUILD (offline, one-off)                    RUNTIME (server)
download_osm.sh                             ├── valhalla/config/valhalla.json
└──> data/<region>.osm.pbf + .poly          ├── valhalla/tiles/ (+ tiles.tar)
         │                                  └── valhalla/elevation/   (for /height)
         ▼                                        │
tools/merge_regions.py                            ▼
└──> data/coverage.osm.pbf                  docker-compose (port 8002)
         │                                  valhalla_service /data/config/valhalla.json 4
         ├──> tools/build_coverage.py           (from the .poly files)
         │    └──> data/coverage.geojson         ─┐
         ├──> tools/extract_restricted_areas.py    ├─> baked into the API image
         │    └──> data/restricted_areas.geojson ─┘
         ▼
build_tiles.sh (needs the merged PBF + elevation)
├──> config/valhalla.json, admins.sqlite, timezones.sqlite
└──> tiles/ + tiles.tar  (grades baked in)
         │
         ▼
download_elevation.sh (from the tiles) ──> elevation/*.hgt.gz
```

Elevation is downloaded for the tiles the graph contains, but the graph needs
elevation to bake grades in. `setup_valhalla.sh` therefore rebuilds the tiles
once more whenever the elevation download adds new files, which happens the
first time a region joins the graph.

## Resources

Measured on 2026-10-11 for the default four regions (6 CPUs, 14 GB RAM, SSD):

| Step | Time | Peak RAM | Output |
|---|---|---|---|
| Merge extracts | 53 s | 6.4 GB | `coverage.osm.pbf`, 1.98 GB |
| Coverage polygons | < 1 s | small | `coverage.geojson`, 16 kB |
| Restricted areas | 150 s | 7.9 GB RSS, mostly the file-backed node index (~2.4 GB of it anonymous) | 2,131 areas, 2.0 MB |
| Config + admins + tiles | ~13 min | up to 8.1 GB (container, page cache included) | 2,107 tiles, 2.7 GB |
| Elevation download | 33 s for the 32 new tiles | small | 205 tiles, 1.2 GB in total |
| Tiles rebuild with new elevation | ~13 min | as above | same tiles, with grades for the new areas |

A first build of a new region therefore takes about 30 minutes plus the
downloads; later rebuilds skip the second tile build. The restricted-areas
step also writes a ~4 GB temporary node index next to its output.

Disk: about 11 GB for a full build (extracts, merged PBF, tiles directory,
`tiles.tar`, elevation), of which only `tiles.tar` and the elevation tiles
(3.9 GB) go to the server.

## Production deployment

To serve routing requests you need exactly:

1. The Docker image: `ghcr.io/valhalla/valhalla:3.8.2`
2. `config/valhalla.json`
3. `tiles/` (or just `tiles.tar`, which the config references as extract)
4. `elevation/` — optional at runtime: `/height` needs it, routing does not
   (grades are already baked into the tiles). Required again whenever you
   rebuild the graph.

You do **not** need: the `.osm.pbf` files, the sqlite files, or any script.
Mount the directory as `/data` and run:

```bash
valhalla_service /data/config/valhalla.json <threads>
```

That is what `docker/docker-compose.dev.yaml` does with `../backend/valhalla:/data`.

The coverage and restricted-areas GeoJSON files are copied into the API image
by the `Dockerfile`, so a data refresh also needs a new API image.

## Regenerating everything from scratch

On a fresh machine (or after wiping `valhalla/`):

```bash
./scripts/setup_valhalla.sh
```

It downloads the default regions (`spain,canary-islands,portugal,andorra`),
merges them, builds the coverage polygons, restricted areas and tiles,
downloads elevation, rebuilds the tiles if the elevation download added
files, starts Valhalla and validates `/status` and `/height`. Then:

```bash
./scripts/smoke_test_height.sh
```

The individual steps, for a partial rebuild:

```bash
./scripts/download_osm.sh spain canary-islands portugal andorra
.venv/bin/python -m tools.merge_regions data/spain.osm.pbf data/canary-islands.osm.pbf \
    data/portugal.osm.pbf data/andorra.osm.pbf
.venv/bin/python -m tools.build_coverage spain canary-islands portugal andorra
.venv/bin/python -m tools.extract_restricted_areas
./scripts/build_tiles.sh
./scripts/download_elevation.sh
./scripts/build_tiles.sh          # again, only if the elevation download added files
```

## Adding a new region

Add an entry to `data/regions.json` with the Geofabrik `url`, its boundary
`poly` (same path with `.poly` instead of `-latest.osm.pbf`) and the ISO 3166-1
alpha-2 `iso` code, then build with the new list:

```bash
./scripts/setup_valhalla.sh --regions spain,canary-islands,portugal,andorra,france
```

Check that the extract really contains what its name suggests (the Spain
extract has no Canary Islands). The merge holds every extract except the
largest in memory, so a second large country raises the peak RAM
accordingly. Change the default list in `setup_valhalla.sh` once the region is
meant to stay.

## Git hygiene

`.gitignore` excludes every large/generated artifact:

- `data/*.osm.pbf`, `data/*.poly` — source data, re-downloadable from Geofabrik
- `valhalla/tiles/`, `valhalla/tiles.tar` — generated by `build_tiles.sh`
- `valhalla/elevation/` — re-downloadable via `download_elevation.sh`
- `valhalla/config/*.sqlite` — generated by `build_tiles.sh`
- `valhalla/valhalla/` — junk path from an earlier manual run (raw Copernicus
  TIFF intermediates); safe to delete from disk

Only code, scripts, docs, `data/regions.json` (the region catalog), the two
GeoJSON files the API image bakes in and
`valhalla/config/valhalla.json` (small, and the canonical reference
configuration) are versioned.
